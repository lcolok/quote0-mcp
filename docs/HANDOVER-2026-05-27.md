## 剩余 3 个未修复问题

### ① VM 沙箱逃逸（`src/react-widgets/core/decorator-sandbox.ts`）

- **风险**: 中-高。当前用 Node.js `vm` 模块运行 LLM 生成的装饰器代码。官方明确说 `vm` 不是安全沙箱。
- **已知绕过**: `Error.prepareStackTrace`、原型链污染、动态属性访问组合。
- **修复**: 安装 `isolated-vm`（V8 Isolate 真正隔离），替换 `vm.runInContext`。
- **代价**: 新增原生依赖（需编译），API 调用方式需小幅调整。

### ② `@ts-nocheck`（`src/api/ax-training-api.ts`）

- **原因**: 该文件动态 import `../../scripts/ax-training/snapshot-manager.js`，但 tsconfig `rootDir` 是 `./src`，不允许引用外部文件。
- **影响**: 整个文件（459 行）的类型检查被禁用，潜在的类型错误被静默忽略。
- **修复**: 将 `scripts/ax-training/` 移入 `src/api/ax-training/`（或修改 `rootDir` 为 `.`）。

### ③ 调度器竞态条件（`src/api/news-scheduler.ts:464-471`）

- **场景**: `if (job.state.running)` 检查和 `job.state.running = true` 之间无原子性。高并发触发时两个请求可同时通过检查。
- **后果**: 重复推送同一内容到设备。
- **修复**: 数据库乐观锁 `UPDATE ... WHERE state != 'running'`，或 Redis 分布式锁。
